成都小厂实习的第三周 ​

时间：2026-08-03 ~ 2026-08-07

心情：被领导连续追问，也在不断补窟窿。

周一：被领导现场检查 ​

照常开周会汇报上周工作。因为上线了 AI 助手，领导听完汇报后很感兴趣，直接走到工位旁看效果。结果现场发现了几处问题。

暴露的问题 ​

  • 召回不准：社区里明明有相关文章，AI 却说没有；有时也召回不到我发的文章。排查后发现 topk 设得比较低，高得分片段先占满了结果，minscore 又设得太低，召回了一些无关内容。
  • 端口报备：端口不能随便写，需要走流程报备。
  • 测试方式不合适：之前为了测试召回，改了“没找到结果不要乱答”的逻辑。后来才发现可以直接进工作流试运行。

新需求与优化 ​

  • 引用跳转：回答中引用的原帖要能点击跳转。我最初想用元数据里的帖子 ID，做完后发现引用标题不对，可能取到了文章的二级标题。后来改为把帖子标题作为权威字段存进元数据。
  • Skill 输出格式：领导指出 Skill 应该直接输出 Markdown，而不是 JSON。流程调整为：生成 Markdown → 发到社区后端 → 解析标题、分类、标签和摘要等元数据 → 发布到社区 → 同步到 AI 平台落库。
  • 鉴权方式：从调用登录接口获取临时 JWT，改成使用 API Key 发布。领导吐槽“一个登录做两天”，其实我只做了半天，中间还处理了引用跳转和后端解析。

领导的问题 ​

我问了一个不太该问的问题：“JWT Token 应该用环境变量获取，还是明文写在配置文件里？”

领导直接反问：“你觉得呢？”

我当然知道不能明文存，只是刚好在和同学讨论，就顺口问了。领导借这个机会提醒我：有主见的人才能驱动 AI。有疑问可以先自己判断、查证，再带着方案去问，不要等别人来追问。

新需求 ​

领导觉得每次更新 Skill 都在群里发消息太麻烦，让我做一个带审核机制的 Skill 上传模块。周二下午开始动工。

周二：Skill 模块与玄学 Bug ​

下午基本完成了 Skill 模块，但遇到一个很难缠的 Bug：上传压缩包后立即解压总是报错。最后交给 GPT 排查，很快就修好了。工具能用，但自己还不够熟。

周三：绿盾疑云与 MCP 初探 ​

SCSS 报错 ​

早上收尾 Skill 模块时，本地前端启动报 SCSS 错误。AI 说文件后面六十多行变成了二进制乱码，修了很久都没用。结果部署上线后又能正常运行。我怀疑是公司的绿盾加密软件导致的。

交付与新需求 ​

给领导展示成果后，他又提了几点：

  • 技能要增加点赞数和下载量统计。
  • 下载链接要让 AI 可以直接 GET 到全部文件，方便自动更新 Skill。
  • 支持 AI 上传 Skill：用户只说一句话，AI 帮忙写好并上传。
  • 让外部 AI 也能接入知识社区、检索知识库。

MCP 服务 ​

领导提到有些服务应该用 MCP 提供。我这才把帖子发布、Skill 上传、知识检索这些功能和 MCP 对上。下午一直在做 MCP，下班时还没写完。晚上在家远程连接测试时又报错，估计是后端服务器关了。1Panel 也要通过 SSH 登录，进不去，只能第二天再排查。

群里领导还在不停给组长提需求。我估计第二天会多出一批任务，得尽快把 MCP 搞定。

周四：大雨迟到与生产事故 ​

早上下大雨，迟到了。更麻烦的是，昨天我用 Jenkins 构建了自己的分支，导致社区后端出问题，还没及时切回稳定分支。领导一早在群里问责，我还在路上，只能先说明情况。

我说昨天下班后发现报错，准备今早处理。领导直接批评：“你们现在学到东西应该很兴奋，不要把这个严重的问题过夜。”话说得很重，但问题确实不该拖到第二天。

到公司后，我先在本地启动后端，发现根本起不来，赶紧切回稳定分支。然后把报错交给 AI，很快解决。接着测试 MCP 服务，确认功能正常后截图交付。

MCP 使用提示 ​

领导让我安装 MCP 时，直接访问了 MCP 地址。我一开始纳闷：这个地址不是给 AI 用的吗？后来才明白，他是让我在那个访问页面上写“如何使用 MCP”的提示，例如“AI 一句话帮你安装”的引导文案。

周五：运维乌龙、评论入库与提示词版本管理 ​

部署乌龙 ​

一大早，运维问我部署的版本对不对。我说如果不要 MCP 就是老版本。结果他部署到了测试环境，我以为他要上正式环境，还帮他改了 IP。后来构建报错，我一看，地址访问不对。说明情况后，领导对我说：“你又不做运维，不要跟运维抢活干。”这次算是把职责边界记住了。

评论是否入库 ​

领导要求把帖子评论也纳入 RAG 知识库。我和组长都觉得全存会有大量“顶楼回复”之类的无用信息，影响知识库质量。领导坚持都要存，理由是：

“自古二楼出人才。很多有用消息在评论里，你不知道它有没有用。大模型训练时不也把‘666’放进去了吗？只要空间够，这些东西都是能存进去、能被查出来的。”

角度确实不一样。

提示词修改引发的问题 ​

我在更新 AI 助手提示词，适配按标签筛选功能。领导正好在用，而我还处在测试阶段，没提前通知他，结果 AI 没有贴出参考源。于是他安排了两件事：

  1. 给 AI 平台单独部署一套生产环境，避免我修改提示词时影响正常使用。
  2. 让组长增加提示词版本管理，支持回滚，防止修改时丢失已有功能。

新页面重构 ​

快下班时，领导又提了新需求：AI 助手不要悬浮在社区右下角，而是新开一个独立页面，还要支持聊天记录和历史对话。搞了一下午，卡在“没有历史对话”的 Bug 上。只能下周继续。

题外话 ​

  • 被组长发现我 Codex 桌宠用的是纳西妲，他还问我是不是还在玩原神。
  • 缺的两个卡也补齐了。

本周反思 ​

维度收获 / 教训
技术学会调 RAG 的 topk 和 minscore，也接触到 MCP 服务封装和提示词版本管理
沟通有问题先思考再问；修改线上配置前必须通知相关人；不要越界帮运维干活
心态被批评时先解决问题；领导的需求背后往往有更深的产品逻辑
习惯严重问题不过夜；有主见才能驱动 AI；测试环境和生产环境要严格隔离

下周目标：修好历史对话 Bug、完善 MCP 文档、推进评论入库策略落地。
