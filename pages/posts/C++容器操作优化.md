### 现代 C++ 容器操作优化指南
算法竞赛对时间和空间都比较敏感。选择合适的数据结构、减少临时对象和不必要的内存分配，可以让代码更简洁，也少一些性能损耗。

---

## 1. 常见容器操作选择指南

| 🏷️ **容器类型**                 | ⚡ **操作**              | 🌟 **推荐使用**   | 🛠️ **理由**                                                                 |
|-----------------------------|-------------------------|------------------|------------------------------------------------------------------------|
| `std::vector` / `std::deque` | `push_back` vs `emplace_back` | **`emplace_back`** | 避免临时对象创建，直接就地构造，性能更高                                       |
| `std::map` / `std::unordered_map` | `insert` vs `emplace`   | **`emplace`**   | 就地构造键值对，无需创建 `std::pair` 临时对象                                |
| `std::set` / `std::unordered_set` | `insert` vs `emplace`   | **`emplace`**   | 避免临时对象，直接构造元素                                                   |
| `std::queue`                 | `push` vs `emplace`    | **`emplace`**   | 对复杂对象（如结构体），`emplace` 避免临时对象开销                             |
| `std::priority_queue`        | `push` vs `emplace`    | **`emplace`**   | 插入复杂类型时，`emplace` 避免创建和移动临时对象，重排时更高效                 |
| **智能指针构造**              | `new` vs `make_shared` / `make_unique` | **`make_shared`** / **`make_unique`** | 避免重复分配内存，更安全高效                                                   |

---

## 2. 使用建议：适用于算法竞赛场景

### 优先使用 `emplace` 和 `emplace_back`
- **适用场景**：需要插入复杂类型对象时，例如 `std::pair` 或自定义结构体，比如构建邻接表、向优先队列插入节点。
- **优势**：
  - 就地构造对象，避免创建临时变量。
  - 减少拷贝和移动操作。

---

### `push` 和 `insert` 的适用场景
- **简单类型或已有完整对象**：如果对象已经存在，例如它是函数的返回值，直接用 `push` 或 `insert` 即可。

---

### 简单类型场景：无需过度优化
- 对 `int`、`double` 这类基本数据类型，`push` 和 `emplace` 的性能基本一致，选可读性更好的写法即可。

---

### 构造智能指针的推荐
- 使用 `make_shared` 或 `make_unique`，避免裸 `new`。算法竞赛通常不涉及复杂内存管理，但这些写法能减少错误。

---

## 3. 快速操作对比表

| 🛠️ **操作类型**       | 🌟 **优先推荐**   | 🎯 **算法竞赛场景**                                            |
|-------------------|------------------|-----------------------------------------------------------|
| **插入到容器末尾**  | `emplace_back`   | 在动态数组（如邻接表）中插入复杂对象或自定义数据结构              |
| **插入到指定位置**  | `emplace`        | 在特定位置插入数据，常见于动态更新问题或需要特定顺序的操作         |
| **插入已构造对象**  | `push` / `insert` | 已有返回结果（如从函数调用中获取值），直接插入容器                 |
| **键值对插入**      | `emplace`        | 使用 `map` 存储值时，直接构造键值对（如动态最优解存储）            |
| **队列操作**        | `emplace`        | 在 `queue` 和 `priority_queue` 中插入复杂对象（如路径、优先级信息） |
| **智能指针构造**    | `make_shared`    | 用于管理复杂结构，减少内存泄漏风险                              |

---

## 4. 针对常见竞赛问题的建议

### 优先队列问题：`std::priority_queue`
- 常见于最短路径问题，例如 Dijkstra。
- 推荐使用 `emplace` 直接构造节点和权值，避免不必要的拷贝。
- 示例代码：
```cpp
typedef pair<int, int> PII;  
priority_queue<PII, vector<PII>, greater<PII>> pq;  
pq.emplace(0, start);  // 直接插入距离与节点信息
```

---

### 图相关问题：邻接表构造
- 常见于深度优先搜索（DFS）、广度优先搜索（BFS）和最短路径问题。
- 推荐使用 `emplace_back` 构建邻接表，减少临时变量。
- 示例代码：
```cpp
vector<vector<PII>> adj(n);  
adj[u].emplace_back(v, weight);  // 直接插入目标节点及权重
```

---

### 动态更新问题：有序容器的选择
- 常见于滑动窗口、区间问题等需要动态维护状态的场景。
- 推荐容器：
  - `std::set`：适合动态维护有序数据，常用 `emplace`。
  - `std::map`：适合动态维护键值对，例如统计出现次数。
- 示例代码：
```cpp
set<int> s;  
s.emplace(value);  // 插入数据并保持有序
```

---

## 5. 小技巧与经验分享

1. **减少临时变量创建**：
   - 涉及路径、节点和优先级等复杂数据结构时，可以优先考虑 `emplace` 和 `emplace_back`。

2. **减少动态内存分配**：
   - 如果会频繁插入元素，可以在初始化时预留空间。
   - 对 `std::vector`，确定数据规模后调用 `reserve(size)`。

3. **高效排序与二分查找**：
   - 使用 `std::sort` 和 `std::lower_bound` 配合容器操作，可以快速定位数据。

4. **选择合适的 STL 容器**：
   - 例如需要两端操作时，可以用 `deque` 替代只支持队尾插入的 `queue`。

---

## 总结：算法竞赛的容器操作最佳实践

- 优先考虑就地构造操作，例如 `emplace` 和 `emplace_back`，减少不必要的拷贝和动态分配。
- 根据问题需求选择 `vector`、`map`、`priority_queue` 等容器。
- 能提前确定规模时，尽量提前分配空间，减少运行中的动态内存分配。
- 在保证代码可读性的前提下关注性能，不必为了“优化”把代码写得难以维护。

---

这些写法覆盖了常见场景，真正做题时还要结合数据规模和时间限制选择。
